# Progress Page Mistake Tag Experiment

This repository demonstrates a lightweight analytics stack for surfacing mistake-tag insights from student assessment attempts. It consists of a FastAPI backend backed by SQLite, a seed/ingestion workflow for the provided CSV, and a static frontend dashboard that surfaces both subtopic-level aggregates (`/subtopics`) and per-student breakdowns (`/student_subtopics`).

## Project structure

```
backend/
  app/
    config.py         # Application settings (database location)
    database.py       # SQLAlchemy engine/session factory
    ingest.py         # CSV ingestion helpers + LLM-backed mistake tagging
    main.py           # FastAPI application
    models.py         # Relational schema (students, subtopics, questions, attempts, tags)
    schemas.py        # Pydantic response models
  requirements.txt    # Python dependencies
  scripts/seed.py     # Convenience script for ingesting the dataset
frontend/
  index.html          # Static dashboard consuming the API
docs/
  index.html          # Copy of the dashboard used for GitHub Pages hosting
Dataset - Progress page test - Sheet1.csv
README.md
```

## Getting started

### 1. Create a virtual environment & install dependencies

```bash
python -m venv .venv
source .venv/bin/activate  # On Windows use `.venv\\Scripts\\activate`
pip install -r backend/requirements.txt
```

### 2. Ingest the sample dataset

Set `OPENAI_API_KEY` (and optionally `OPENAI_MODEL`) in your environment before running ingestion if you would like to generate mistake categories with OpenAI. Without these variables the code falls back to deterministic placeholders suitable for local development and testing.

```bash
python backend/scripts/seed.py
```

By default the data is loaded into `backend/data/app.db`. You can override the location by setting `APP_DATABASE_URL` before running the seed script (e.g. `export APP_DATABASE_URL=sqlite:///my.db`).

### 3. Run the API & frontend

```bash
uvicorn backend.app.main:app --reload
```

Visit `http://127.0.0.1:8000/` to view the dashboard. Use the **View** selector to switch between the subtopic summary and student-level tables. The FastAPI docs (including schemas for `/subtopics` and `/student_subtopics`) are available at `http://127.0.0.1:8000/docs`.

### Hosting the dashboard on GitHub Pages

1. Keep the `docs/index.html` file in sync with the frontend source by running:

   ```bash
   python scripts/sync_frontend.py
   ```

2. Commit and push the generated `docs/index.html`.

3. In your GitHub repository, open **Settings → Pages**, choose **Deploy from a branch**, and select the `main` branch with the `/docs` folder. Save the configuration to enable Pages.

4. GitHub will publish the site at `https://<your-username>.github.io/<repository>/`. Load that URL, set the **API base URL** field to where your FastAPI backend is running (for example `https://your-api.example.com` or `http://localhost:8000`), and the preference will be remembered in `localStorage`.

### 4. Run the automated tests

```bash
pytest
```

The tests confirm that the ingestion flow and aggregation logic remain stable when the LLM classifier is substituted with a deterministic stub for offline runs.

## Data model & mistake categories

The relational schema is intentionally simple and maps directly to the CSV columns:

| Table | Purpose |
| --- | --- |
| `students` | Unique learners identified by `student_id`. |
| `subtopics` | Learning objectives (CSV `description`) grouped by topic (`name`) and subject. |
| `questions` | Items attempted inside a subtopic (`kid`, `q_text`, `q_text1`, `q_image`). |
| `attempts` | Individual student responses including raw marks and free-text answers. |
| `mistake_tags` | Short 1–3 word categories assigned to incorrect attempts. |
| `attempt_mistake_tags` | Association table supporting multi-tag assignments per attempt. |

Every CSV row becomes a single `attempt` joined to a `student`, `subtopic`, and `question`. Mistake categories are generated by `classify_mistake` in `backend/app/ingest.py`. The function flags blank responses immediately, marks fully correct attempts with the reserved `null` category, and otherwise sends the question text, reference answer, student answer, and marks to an OpenAI-powered prompt. The LLM is instructed to return a concise 1–3 word description (for example “Concept Error” or “Partial Understanding”). When the API key or OpenAI dependency is unavailable, the logic falls back to deterministic heuristics so tests and offline ingestion still succeed.

## API endpoints

### `/subtopics`

`GET /subtopics` returns aggregated counts of attempts per subtopic/tag combination. Query parameters allow lightweight analytics:

- `tag` – exact tag filter (e.g., `blank_response`).
- `subtopic` – case-insensitive substring filter on the subtopic description.
- `sort_by` – one of `subtopic`, `tag`, or `count`.
- `sort_dir` – `asc` or `desc`.

### `/student_subtopics`

`GET /student_subtopics` returns one row per `(student_id, subtopic)` pair alongside the union of mistake tags applied to that student's attempts. Supported query parameters mirror the dashboard controls:

- `tag` – only return rows that include the specified tag.
- `subtopic` – case-insensitive substring filter on the subtopic description.
- `student_id` – restrict results to a specific learner.
- `sort_by` – one of `student`, `subtopic`, `tag_count`, or `attempts`.
- `sort_dir` – `asc` or `desc`.

The frontend dashboard uses these parameters to provide filtering and sorting controls directly in the UI for both views.

## Extending the taxonomy

1. **Add the new definition** to `TAG_DEFINITIONS` in `backend/app/ingest.py`, including a human-readable description.
2. **Update `derive_tags`** to emit the new tag when its conditions are met.
3. **Re-run the seed script** (or call `/ingest`) to backfill historic attempts with the updated logic.
4. **Adjust tests** in `tests/test_ingestion.py` if additional deterministic assertions are required.

Because tags live in their own table, the taxonomy can evolve without any schema changes. New tags will automatically appear in the `/subtopics` aggregation and therefore in the frontend dashboard.

## Seeding & re-running ingestion

- `python backend/scripts/seed.py` ingests the canonical CSV into the default SQLite database.
- `POST /ingest?csv_path=/absolute/path/to/file.csv` provides an API-based alternative for new datasets.
- Re-running either option is idempotent; existing records are updated in place when primary keys match.

## Development tips

- Use the FastAPI docs (`/docs`) to quickly test query parameters and inspect the API schema.
- The database lives in SQLite, so `sqlite3 backend/data/app.db` is handy for ad-hoc exploration.
- To serve the static dashboard from another tool (e.g. Vite), point it at the `/subtopics` endpoint—the API already includes permissive CORS headers.
