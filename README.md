# Progress Page Mistake Tag Experiment

This repository demonstrates a lightweight analytics stack for surfacing mistake-tag insights from student assessment attempts. It consists of a FastAPI backend backed by SQLite, a seed/ingestion workflow for the provided CSV, and a static frontend dashboard that consumes an aggregated `/subtopics` endpoint.

## Project structure

```
backend/
  app/
    config.py         # Application settings (database location)
    database.py       # SQLAlchemy engine/session factory
    ingest.py         # CSV ingestion helpers + tagging heuristics
    main.py           # FastAPI application
    models.py         # Relational schema (students, subtopics, questions, attempts, tags)
    schemas.py        # Pydantic response models
  requirements.txt    # Python dependencies
  scripts/seed.py     # Convenience script for ingesting the dataset
frontend/
  index.html          # Static dashboard consuming the API
Dataset - Progress page test - Sheet1.csv
README.md
```

## Getting started

### 1. Create a virtual environment & install dependencies

```bash
python -m venv .venv
source .venv/bin/activate  # On Windows use `.venv\\Scripts\\activate`
pip install -r backend/requirements.txt
```

### 2. Ingest the sample dataset

```bash
python backend/scripts/seed.py
```

By default the data is loaded into `backend/data/app.db`. You can override the location by setting `APP_DATABASE_URL` before running the seed script (e.g. `export APP_DATABASE_URL=sqlite:///my.db`).

### 3. Run the API & frontend

```bash
uvicorn backend.app.main:app --reload
```

Visit `http://127.0.0.1:8000/` to view the dashboard. The FastAPI docs (including the `/subtopics` schema) are available at `http://127.0.0.1:8000/docs`.

### 4. Run the automated tests

```bash
pytest
```

The tests confirm that the ingestion heuristics and aggregation logic produce deterministic results for the supplied dataset.

## Data model & tagging heuristics

The relational schema is intentionally simple and maps directly to the CSV columns:

| Table | Purpose |
| --- | --- |
| `students` | Unique learners identified by `student_id`. |
| `subtopics` | Learning objectives (CSV `description`) grouped by topic (`name`) and subject. |
| `questions` | Items attempted inside a subtopic (`kid`, `q_text`, `q_text1`, `q_image`). |
| `attempts` | Individual student responses including raw marks and free-text answers. |
| `mistake_tags` | Normalised taxonomy describing the nature of an attempt. |
| `attempt_mistake_tags` | Association table supporting multi-tag assignments per attempt. |

Every CSV row becomes a single `attempt` joined to a `student`, `subtopic`, and `question`. Tags are generated by the heuristics in `backend/app/ingest.py`:

| Tag | Criteria |
| --- | --- |
| `blank_response` | The learner left the answer blank or only whitespace. |
| `conceptual_gap` | Mark awarded is `0`, signalling a fundamental misunderstanding. |
| `partial_understanding` | Mark awarded is greater than `0` but less than the available mark. |
| `mastered` | Full marks were awarded for the attempt. |
| `needs_revision` | Student score is below the available mark, flagging the subtopic for revision. |
| `review_with_teacher` | An incorrect non-blank response that could anchor targeted feedback. |

Multiple tags can be attached to a single attempt (e.g., a blank answer that scores zero will carry both `blank_response` and `conceptual_gap`).

## `/subtopics` endpoint

`GET /subtopics` returns aggregated counts of attempts per subtopic/tag combination. Query parameters allow lightweight analytics:

- `tag` – exact tag filter (e.g., `blank_response`).
- `subtopic` – case-insensitive substring filter on the subtopic description.
- `sort_by` – one of `subtopic`, `tag`, or `count`.
- `sort_dir` – `asc` or `desc`.

The frontend dashboard uses these parameters to provide filtering and sorting controls directly in the UI.

## Extending the taxonomy

1. **Add the new definition** to `TAG_DEFINITIONS` in `backend/app/ingest.py`, including a human-readable description.
2. **Update `derive_tags`** to emit the new tag when its conditions are met.
3. **Re-run the seed script** (or call `/ingest`) to backfill historic attempts with the updated logic.
4. **Adjust tests** in `tests/test_ingestion.py` if additional deterministic assertions are required.

Because tags live in their own table, the taxonomy can evolve without any schema changes. New tags will automatically appear in the `/subtopics` aggregation and therefore in the frontend dashboard.

## Seeding & re-running ingestion

- `python backend/scripts/seed.py` ingests the canonical CSV into the default SQLite database.
- `POST /ingest?csv_path=/absolute/path/to/file.csv` provides an API-based alternative for new datasets.
- Re-running either option is idempotent; existing records are updated in place when primary keys match.

## Development tips

- Use the FastAPI docs (`/docs`) to quickly test query parameters and inspect the API schema.
- The database lives in SQLite, so `sqlite3 backend/data/app.db` is handy for ad-hoc exploration.
- To serve the static dashboard from another tool (e.g. Vite), point it at the `/subtopics` endpoint—the API already includes permissive CORS headers.
